# USM-6502 – erstes emuliertes Zielsystem

**Status:** First executable software-only machine profile, using the third-party `py65` Python CPU emulator. This is a minimal SBC and **not yet** a complete interactive monitor computer, a C64 or an Apple II.

## Hardware-independent virtual machine

| Address | Device | Function |
| --- | --- | --- |
| `$0000–$7FFF` | 32 KiB RAM | Read/write |
| `$8000` | Synthetic UART TX | Writes append one ASCII byte to output |
| `$8001–$DFFF` | Unmapped | Decode fault |
| `$E000–$FFFF` | 8 KiB ROM | Read-only boot firmware |

The included ROM is original project code, not an extracted proprietary ROM. It prints `USM-6502 OK` through the UART and enters an idle loop. It demonstrates reset-vector fetching, instruction execution and USP-mapped memory accesses. A genuine monitor with commands, input, timer and interrupt handling is a later milestone.

## Run

```bash
python -m pip install -e ".[6502,web,test]"
python -m usm.cli 6502
```

The CPU core is `py65`, not a new hand-written complete 6502 implementation. Verify its upstream license and pin a tested version before release.

## Optional real-chip transition

A future 6502 daughterboard must implement clock/reset, IRQ/NMI, address/data lanes, R/W, safe 5V level shifting, timing classes and a deterministic bus bridge. The machine profile and memory map must remain unchanged. A hardware backend must not be selected without successful discovery, electrical validation and controlled state transition.

## Acceptance levels

1. **Current initial test:** Reset vector, ROM execution, UART output, RAM and ROM access.
2. **Interactive monitor:** Input, memory read/write, program loading, breakpoints and debugging.
3. **Peripheral completeness:** Timer, IRQ/NMI, serial status/control and snapshot support.
4. **Hardware-in-the-loop:** Run identical synthetic ROM tests on software CPU and physical CPU card.
